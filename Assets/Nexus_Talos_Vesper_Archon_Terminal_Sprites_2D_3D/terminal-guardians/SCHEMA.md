# Indexed sprite format, version 1

`manifest.json` maps each character to its two sprite files:

```json
{"schema_version":1,"characters":{"nexus":{"name":"Nexus","styles":{"2d":"sprites/nexus/2d.json","3d":"sprites/nexus/3d.json"}}}}
```

Each sprite file uses this shape:

```json
{
  "schema_version": 1,
  "character": "nexus",
  "style": "2d",
  "width": 64,
  "height": 64,
  "actions": {
    "standing": {"fps":6,"loop":true,"frames":[[[4096,-1]]]}
  }
}
```

Each frame is a flat, row-major run-length encoded array of `[count, color_index]` pairs. Every decoded frame contains exactly `width × height` pixels. `-1` means transparent. Indices `0..255` address the standard xterm 256-color palette. There is no per-frame palette.

Action identifiers: `standing`, `walking`, `running`, `jumping`, `falling`, `death`, `hit`, `attack_1`, `attack_2`, `attack_3`, `flying`. Every action declares its own FPS and loop flag. One-shot actions keep their final pose; the death action does not cycle back to life.

The 3D style means a shaded voxel or isometric render exported as flat animation frames. The JSON contains no mesh or rig.

The local browser preview reads `preview-data.js`, generated by `python build_preview_data.py`. That file assigns `{manifest, sprites}` to `window.SPRITE_PACK`, with `sprites[character][style]` holding the complete sprite object. This avoids browser restrictions on fetching JSON through `file://`. The builder also writes `preview-standalone.html`, which embeds the same data in one file.
